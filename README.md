# CLB Lập trình PTIT

## 1. Giới thiệu CLB

**CLB Lập trình PTIT** là cộng đồng dành cho sinh viên yêu thích công nghệ, lập trình và phát triển phần mềm.

Điểm nổi bật của CLB là **học tập qua dự án thực tế**, chia sẻ kiến thức và hỗ trợ thành viên cùng tiến bộ. Thành viên có thể tham gia workshop, hoạt động nhóm và các cuộc thi lập trình.

## 3. Hướng dẫn gia nhập

1. Đăng ký tham gia CLB qua biểu mẫu tuyển thành viên do CLB cung cấp.
2. Tham gia kênh thông báo chính thức và đọc nội quy.
3. Cài đặt Git trên máy tính và tạo tài khoản GitHub.
4. Sao chép repository tài liệu của CLB về máy bằng lệnh:

   ```bash
   git clone https://github.com/ptit-programming-club/onboarding.git
   cd onboarding
   ```

5. Tạo nhánh riêng, cập nhật tài liệu và gửi Pull Request để Ban Kỹ thuật xem xét.

   ```bash
   git checkout -b docs/ten-cua-ban
   git add README.md
   git commit -m "docs: update onboarding guide"
   git push -u origin docs/ten-cua-ban
   ```

   Sau đó, mở repository trên GitHub và tạo Pull Request. Chỉ sử dụng URL repository chính thức do CLB cung cấp.

## 4. Checklist nhiệm vụ thành viên mới

- [x] Đọc README và nội quy CLB.
- [x] Tham gia kênh thông báo chính thức.
- [ ] Hoàn thiện hồ sơ thành viên.
- [ ] Cài đặt Git và tạo tài khoản GitHub.
- [ ] Đọc quy trình làm việc với branch và Pull Request.
- [ ] Tham gia buổi định hướng thành viên mới.

## 5. Lưu ý quan trọng

> **Deadline:** Hoàn thành checklist gia nhập trong vòng **7 ngày kể từ ngày được xác nhận trở thành thành viên**.
>
> **Quy tắc ứng xử:**
> - Giao tiếp lịch sự, tôn trọng mọi thành viên và góp ý tập trung vào vấn đề, không công kích cá nhân.
> - Không chia sẻ thông tin nội bộ, mật khẩu, token truy cập hoặc dữ liệu cá nhân ra bên ngoài.
> - Khi đóng góp mã nguồn hoặc tài liệu, hãy mô tả thay đổi rõ ràng và kiểm tra nội dung trước khi gửi Pull Request.
> - Nếu cần hỗ trợ, hãy hỏi đúng kênh và cung cấp thông tin lỗi cụ thể.

## Quy trình cập nhật tài liệu

1. Tạo nhánh mới cho thay đổi.
2. Chỉnh sửa README và kiểm tra phần Preview trên GitHub.
3. Gửi Pull Request để người phụ trách rà soát.
4. Chỉ hợp nhất thay đổi sau khi được duyệt.
